🎵 ISG (Incremental Static Generation)

Otimização do Build Docker do Amazarashi

📊 Visão Geral

graph LR
    A["🐳 Docker Build"] -->|DATABASE_URL| B["Next.js Build"]
    B -->|generateStaticParams| C["Pre-renderiza Slugs"]
    C -->|Gera HTML Estático| D[".next/out"]
    D -->|Deploy| E["🚀 Produção"]
    E -->|Hora 1| F["✅ Serve HTML Cached"]
    E -->|Hora 3600| G["🔄 Revalida em BG"]

🔨 Processo de Build

sequenceDiagram
    participant Build as Docker Build
    participant DB as Banco de Dados
    participant Next as Next.js
    participant Out as .next/out

    Build->>Next: npm run build
    Next->>Next: Executa generateStaticParams()
    Next->>DB: Busca todos os slugs
    DB-->>Next: [album-1, album-2, ...song-1, song-2]
    
    Note over Next: Pre-renderiza cada página
com dados do banco
    
    Next->>Out: Salva /album/album-1/index.html
    Next->>Out: Salva /album/album-2/index.html
    Next->>Out: Salva /musica/song-1/index.html
    Out-->>Build: ✅ Build Completo!

⚡ Runtime em Produção

sequenceDiagram
    participant User as Usuário
    participant Prod as Produção
    participant Cache as Cache HTML
    participant Server as Next.js Server
    participant DB as Banco de Dados

    User->>Prod: GET /album/album-1
    Prod->>Cache: Busca HTML cached
    Cache-->>Prod: ✅ Encontrado!
    Prod-->>User: Serve HTML instantaneamente

    Note over Prod: Revalidação em Background
(após 3600s)
    
    Prod->>Prod: 3600s passados
    Prod->>Server: Regenera /album/album-1
    Server->>DB: Busca dados atualizados
    DB-->>Server: Retorna dados
    Server->>Cache: Atualiza Cache
    Cache-->>Prod: ✅ Pronto para próximo request!

🔄 Comparação: Antes vs Depois

❌ Antes (Sem ISG)

  • Build SEMPRE precisa do banco
  • Falha se banco está down
  • Build lento: todas as páginas
  • Request → Renderiza → Usuário (lento)
  • Sem cache entre requests
  • Alto load no banco durante build

✅ Depois (Com ISG)

  • Build pode rodar sem banco
  • Resiliência a falhas
  • Build mais rápido
  • Request → Serve HTML cached (rápido)
  • Cache reutilizado entre requests
  • Banco chamado apenas para revalidar

📋 Timeline de Implementação

1. Páginas Estáticas

Adicionado export const revalidate = 3600 em:
/, /albuns-e-discos, /biografia, /videoclipes

2. Páginas Dinâmicas

Adicionado revalidate em:
/album/[slug], /musica/[slug]

3. Sitemap

Adicionado revalidate = 3600 em sitemap.ts

4. Configuração Docker

Pass DATABASE_URL como build arg para pré-renderizar com dados

5. Deploy

Todas as páginas serão pré-renderizadas e servidas como HTML estático

✨ Benefícios

⚡ Performance

HTML estático é servido instantaneamente, sem renderização no servidor

🔄 Escalabilidade

Revalidação em background não bloqueia requests de usuários

💪 Resiliência

Build funciona sem banco de dados

📦 Deployment Rápido

Menos tempo esperando build, mais tempo produzindo

💾 Menos Carga no BD

Reduz drasticamente queries durante build

🎯 Flexibilidade

Novo conteúdo (admin) renderiza em runtime com fallback

🐳 Como Usar com Docker

Build COM acesso ao banco (Recomendado):

docker build --build-arg DATABASE_URL="postgresql://user:pass@host/db" .

Build SEM acesso ao banco (ISG renderiza em runtime):

docker build .
